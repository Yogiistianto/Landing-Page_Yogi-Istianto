# antislop Audit #001 — 2026-11-06

**Project:** Yogi Istianto — @bankerdapatcuan Landing Page (Next.js)
**Scope:** Full page audit, with focus on Hero Section + InteractiveLanyardCard
**Design Read:** Personal brand landing page for a digital-product educator targeting Indonesian full-time employees, dark theme with emerald + yellow accent, dial ENERGY 2 / RHYTHM 2 / MOTION 2 (inferred from existing output; no DESIGN.md exists).

---

## Findings

### HIGH Priority (Hard Gate violations)

| # | Rule | File(s) | Finding |
|---|------|---------|---------|
| 1 | R-02 | `layout.tsx:19`, `Footer.tsx:54` | **Em dash (`—`) in UI text.** Title metadata `Yogi Istianto — @bankerdapatcuan` and footer copyright both use an em dash. Replace with a pipe, comma, or bullet separator. |
| 2 | R-17 | `portfolioData.ts:13-18`, `HeroSection.tsx:99`, `StatsBar.tsx`, `FeatureSection.tsx:89`, `HeroSection.tsx:169` | **Unverified statistics displayed as real.** "3.000+", "500K+", "2M+", "1.2M views", "2.000+ member" are shown without a real, verifiable source. If these are real numbers, add a comment citing the source. If not, they must be removed or replaced with `[REAL DATA]` placeholders. |
| 3 | R-18 | `portfolioData.ts:77-81`, `TestimonialSection.tsx` | **Testimonials cannot be verified.** "Bambang S.", "Amir M.", "Supriadi" use initial-avatars and short names. If these are real people with real quotes, add verifiable attribution (full name, link to original post, screenshot). If fabricated, remove the entire section. |
| 4 | R-23 | `HeroSection.tsx:174` | **Floating badge "📈 Growth Creator" created without instruction.** This decorative badge was added by the AI without the user requesting it. Either confirm it with the owner or remove it. |
| 5 | R-26 | `Footer.tsx:36-49` | **Two dead links in footer.** The Film icon and MessageCircle icon both link to `href="#"` with no real destination and no visible "Coming soon" label. Either give them real URLs or remove them. |
| 6 | R-26 | `FeatureSection.tsx:53`, `StepsSection.tsx:46`, `EarningsHighlight.tsx:36` | **Non-interactive cards styled as interactive.** Feature cards, step cards, and earnings items have `cursor-pointer`, `whileHover` scale/lift, and `card-glow` but clicking them does nothing. A card that signals "click me" but has no action is a dead control. Remove the interactive affordances or give them a real action. |
| 7 | R-39 | All components | **No `cursor: pointer` on actual interactive elements via base CSS.** Buttons and links do not have a global `cursor: pointer` rule set in the base CSS layer. Meanwhile, non-interactive `div` elements get `cursor-pointer` via Tailwind classes (finding #6). The requirement is reversed. |
| 8 | R-39 | All `motion.div` with `whileHover` | **Non-essential motion has no `prefers-reduced-motion` stop.** The idle lanyard sway runs infinitely (>5s) with no pause control and no reduced-motion media query. Every scroll-reveal animation, hover lift, and sway animation ignores `prefers-reduced-motion: reduce`. |
| 9 | R-39 | `HeroSection.tsx:23` | **Sparkles icon lacks `aria-hidden="true"`.** Decorative Lucide icons throughout (Sparkles, Target, BarChart3, Award, Play, Camera, etc.) are missing `aria-hidden="true"` and their parent elements lack accessible text. |
| 10 | R-40 | `HeroSection.tsx:130-136` | **Hero profile image lacks `fetchpriority="high"`.** The profile photo in the hero card is an `<Image>` but does not set `priority` (Next.js equivalent of `fetchpriority="high"`). The hero section's main visual should load eagerly. |

### MEDIUM Priority (Purpose-Gate violations — technique without written purpose)

| # | Rule | File(s) | Finding |
|---|------|---------|---------|
| 11 | R-01 | `CtaSection.tsx:16` | **Emerald gradient CTA block with no written purpose.** `bg-gradient-to-br from-emerald-600 via-emerald-700 to-teal-800` covers an entire section. Why this gradient and not a flat color? No purpose documented. |
| 12 | R-04 | `HeroSection.tsx:23`, `CtaSection.tsx:28` | **Sparkles icon used as a generic decorator.** Sparkles is listed as a slop-pattern icon (Part 1: "Sparkle, Star, Magic"). It appears in the Hero badge and CTA badge without written relevance to the content. |
| 13 | R-09 | `HeroSection.tsx:17-25`, `FeatureSection.tsx:18`, `CourseSection.tsx:18`, `TestimonialSection.tsx:27`, `CtaSection.tsx:26`, `EarningsHighlight.tsx:69` | **Capsule badges above every section heading.** Six of eight sections have an identical pattern: pill badge with icon + thin border + small text, placed directly above the heading. This is the "Eyebrow Badge Above the Headline" slop pattern at scale. One or two are fine with purpose; six in a row with identical styling is pattern-without-purpose. |
| 14 | R-12 | `InteractiveLanyardCard.tsx:31` | **Triple-stacked shadow on the lanyard card.** `dynamicBoxShadow` combines a displacement shadow + emerald glow + white border-glow. This complex shadow is the card's only visual, so it may be justified, but the purpose is not written. |
| 15 | R-19 | All sections | **Template animation pattern.** Every single element on the page uses the identical animation: `initial={{ opacity: 0, y: 15 }} whileInView={{ opacity: 1, y: 0 }} transition={{ type: 'spring', stiffness: 120, damping: 20 }}` with staggered delays. This is the "every element uses Fade Up" slop pattern. No UX purpose is written for any of these. |
| 16 | R-19 | `InteractiveLanyardCard.tsx:146` | **Idle sway animation runs indefinitely.** The lanyard card rotates back and forth `[-1.2, 1.2, -1.2]` on `repeat: Infinity, duration: 4.5`. Motion longer than 5s without a pause control violates R-39, and the infinite loop has no written UX purpose. |

### LOW Priority (Quality Lock violations — consistency)

| # | Rule | File(s) | Finding |
|---|------|---------|---------|
| 17 | R-05 | `page.tsx` | **AI template page structure.** The section order is: Hero → Stats Bar → Features → Earnings → Course → Steps → Testimonials → FAQ → CTA → Footer. This is the classic AI landing page template (Hero + stats + feature grid + pricing + 3-step how-it-works + testimonials + FAQ + CTA). The "Steps" section is exactly "How It Works in 3 steps with icons and numbers." |
| 18 | R-05 | All sections | **Uniform section rhythm.** Every section uses centered title + subtitle + grid of identically-styled cards. There is no compositional variation between sections (all follow the same internal layout pattern). This contradicts the inferred RHYTHM 2 dial. |
| 19 | R-11 | All components | **Uniform border-radius.** Almost every component uses `rounded-2xl` or `rounded-3xl`. Buttons, cards, badges, inputs, avatars, icon containers all share the same large radius with no hierarchy-driven variation. |
| 20 | R-14 | `CourseSection.tsx:44-65` | **Six identical feature cards.** All course module cards have the same size, padding, layout, icon treatment, and hover effect. No visual hierarchy distinguishes the more important modules. |
| 21 | R-20 | Entire project | **Weak visual identity.** If the logo/name were swapped, this design could belong to any dark-themed digital product landing page. The emerald+yellow on dark is generic. There is no identity motif, no distinctive typographic gesture, nothing that says "this belongs to @bankerdapatcuan specifically." |
| 22 | R-29 | Entire project | **Accent color overuse.** Emerald-400/500 appears on: badges, icons, buttons, card borders (hover), glow effects, stat numbers, gradient text, shadows, lanyard rope, and backgrounds simultaneously. One accent color on everything is the "Excessive Accent Color" pattern. |
| 23 | R-31 | Entire project | **No design decisions documented.** There is no DESIGN.md, no written reasons for color choice, typography choice (Plus Jakarta Sans + Inter — why these?), layout decisions, or spacing system. Every decision lacks its one-line reason. |
| 24 | R-06 | `HeroSection.tsx:119` | **Monospace font used without reason.** "Digital Asset Pass" and "NO. 0824-YI" use `font-mono` for a "terminal/tech" aesthetic. The product is a digital asset course for bank employees, not a developer tool. No brand-character reason is written. |
| 25 | R-05 | `EarningsHighlight.tsx:20-26` | **macOS window chrome dots.** The earnings card has three colored dots (red, yellow, green) mimicking a macOS terminal window. This is the "Fake Terminal Window" slop pattern variant. A product catalog for a bank employee educator has no reason for OS chrome decoration. |
